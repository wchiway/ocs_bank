# 高优先级解决方案

基线：`3ad34f0`。范围是现有问题修复，不包含管理 UI、多用户、RAG 或多模型路由。先合并本方案，再从更新的 main 创建实施 worktree。

## H1：按题型校验答案

- JSON 解析后增加业务校验，缓存读取和人工导入采用同一规则。
- 单选只接受一个答案；选项能够无歧义解析时要求答案属于选项内容，不猜测字母答案或模糊匹配。
- 多选按 `###` 分隔、去重并验证选项归属；填空保留顺序和重复内容，拒绝空分段。
- 判断题将明确的对/错、正确/错误、true/false 规范为对/错。
- 未提供选项或选项无法可靠分段时，只做能够确定的结构校验，保留未知题型的兼容性。
- 更新 AI 缓存策略版本，防止旧的未校验记录继续命中；保留 OCS HTTP 和返回结构。

验收：四种题型的正反例、歧义选项、未知题型、空分段、重复答案；无效生成不入库；错误不会被缓存。格式通过不等于事实正确。

## H2：人工题库与 AI 缓存分离

- 新建 `reviewed_answers`，题目身份由规范题目、原始选项、规范题型决定，不绑定模型、协议、提示词版本或 TTL。
- 查询顺序：人工题库 → AI 缓存 → 合并请求/限流 → AI → 校验/缓存；等待调用开始前再次检查人工题库。
- 迁移既有 `legacy-reviewed`：仅迁移未显式失效且同题答案一致的记录；冲突记录保留在旧表待复核，不任意选取答案。不迁移普通 AI 记录为人工答案。
- 旧库导入写入人工题库，幂等且不覆盖已有人工答案，AI 缓存不能阻挡人工导入。
- 升级迁移器以按版本顺序执行迁移；未知较新版本继续拒绝启动。

验收：从 v1 数据库升级；人工答案在换模型、缓存过期后仍命中；人工答案优先；冲突与显式失效记录不被复活；重复导入、失败回滚和重启持久化。

## H3：独立上游调用记录

- 新建追加式 `upstream_calls`，每次实际 HTTP 尝试独立记录协议、模型、开始时间、耗时、HTTP 状态、尝试序号、结果类别与可用的 usage。
- 区分缺少 usage 和真实 0 token；仅将上游返回且通过基础数值校验的 usage 纳入已知消耗。网络中断或无 usage 时费用未知，不声称完整账单。
- 缓存命中不产生上游调用记录；重试各有一条记录；答案覆盖或清理不改变历史调用。
- 不记录请求题目、答案、上游响应体、端点或密钥。调用记录写入有独立短超时，失败记录脱敏错误且不抹掉有效答案。

验收：成功/重试/认证错误/格式错误/取消等尝试计数；usage 缺失；缓存命中不计费；写入失败不破坏查询。

## 发布与回退

实施 PR 运行 gofmt、go build、go vet、go test、go test -race 和 Node 测试。升级前由部署操作者使用一致性数据库备份；旧二进制无法读取新 schema，回退需要恢复升级前备份。本次仅用临时库与模拟上游测试，不访问真实配置、dotenv 或数据库。
