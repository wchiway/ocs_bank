# 验证记录与上线检查

## 自动化范围

- 配置校验、访问令牌、限流、OCS 成功/未找到/错误契约。
- Chat Completions、Messages、Responses 的请求字段、鉴权、端点覆盖、多内容块解析。
- 拒答、截断、空/非法 JSON、401/403/429/5xx、超时、重试预算、重定向和响应体限制。
- 缓存持久化、唯一性、题目选项隔离、失效、过期和未来 schema 拒绝。
- 相同请求合并、单个与全部等待者取消、并发/队列上限、失败不缓存、写入失败仍返回有效答案。
- 旧库只读、无效/重复/冲突过滤、原子导入、重复导入保护、目标不可等于源。
- 启动真实 Go 服务进程，通过 HTTP 验证令牌、查询、缓存重启持久性、日志脱敏与 SIGTERM 退出。
- Node.js 执行 OCS 示例中的实际 JavaScript handler。

本地执行 gofmt、go vet、go test、go test -race、go build、CGO_ENABLED=0 构建和 Node 测试；CI 运行相同检查并构建容器镜像。测试均使用临时文件和模拟上游。

## 原仓库快照预检

对本地 legacy/python 分支中的数据库副本执行只读预检：共 2 条记录，均因题型缺失或未知而排除，可导入 0 条。原始数据库未修改，也未执行导入。

## 部署环境仍需验证

真实 AI 服务商响应与用户实际模型能力，以及浏览器/油猴/OCS 的端到端联调，需要部署环境的凭据和浏览器。本次自动测试不替代这些现场检查。

- 设置实际模型及密钥，发送一条题目并确认答案；再次发送确认缓存命中。
- 在 OCS 中导入 examples/ocs.json，确认 URL、@connect 权限和访问令牌。
- 检查单选、多选、判断、填空格式；多答案采用 ### 分隔。
- 核对反向代理超时大于服务配置，端口与持久卷权限正确。
- 切换前备份数据，按照 migration.md 验证回退。

GitHub 私密仓库的服务端分支保护当前受账户套餐限制（403）；所有变更仍必须由任务分支通过 PR 合并。
