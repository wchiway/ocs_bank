# 中优先级解决方案

依赖：先完成 [高优先级方案](remediation-high.md)。每个阶段从更新的 origin/main 创建 worktree，检查通过后用 PR squash merge。

## M1：可诊断的日志与运行指标

- 统一有限集合的结果分类：invalid、not_found、refused、auth、rate_limit、busy、timeout、canceled、protocol、storage、unavailable。
- 查询日志记录请求 ID、总耗时、命中层级和结果；共享生成日志记录排队和生成耗时，不把共享调用虚假归属于某一个等待者。
- 提供受现有服务令牌保护的 JSON 运行统计，包括请求、缓存/人工题库命中、排队、调用与写入失败；不记录题目或秘密，不引入高基数标签。
- 保留 `/healthz` 存活检查；增加 `/readyz` 检查服务关闭状态与受限时的数据库连通性，不调用 AI。
- 数据库失败映射服务不可用，避免全部伪装为上游失败；OCS 成功结构保持不变。

验收：日志脱敏与类别、统计计数、认证保护、readiness 超时和服务关闭；race 检查。

## M2：安全的数据维护命令

- 新增独立 `ocs-maintain`，显式使用 `-database`，不加载服务配置或 dotenv。
- 清理支持过期/失效 AI 缓存、可选模型筛选、可选调用历史保留天数；默认只预览，显式 `-apply` 才修改。采用有上限的批次，不删除人工题库。
- 支持统计汇总；统计基于独立调用记录，区分已知 token 与缺少 usage 的调用。
- 备份使用 SQLite 一致性快照（VACUUM INTO），拒绝覆盖已有目标；恢复只写入不存在的新目标，验证备份完整性和 schema，并要求停止服务后由操作者切换文件。
- 文档给出容器外维护和回退步骤、批次限制、磁盘空间和调用记录保留策略。

验收：预览不修改行；筛选与批次边界；人工答案保留；活跃 WAL 数据一致备份；目标已存在时拒绝；恢复数据可查询；全程无需 AI 密钥。

## M3：稳定发布标签保护

主线 PR #11 已实现正式版发布完整版本号与 latest、预发布不覆盖 latest。在此基础上：

- 版本镜像始终发布；latest 单独按 digest 提升，稳定发布的提升步骤串行化。
- 提升前重新读取远程正式版本标签并比较 SemVer；有更高正式版本时跳过旧版本的 latest 提升，避免重跑覆盖。
- 失败应显式失败而不是假装 latest 已更新；预发布不进入提升步骤。
- 覆盖版本排序、旧版重跑、同版本重跑、预发布以及 workflow 连接测试。
- 旧 tag 使用当时的 workflow，无法被本次改动追溯修正；保护仅对包含新流程的发布有效，不触发真实版本发布。

验收：本地 Node 行为测试和 workflow 校验；完整 Go 检查；PR CI 通过。实现后更新 README 和 releases 文档。
