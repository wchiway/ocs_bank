# 旧 Python 数据迁移与回退

## 1. 创建一致备份

停止旧服务后复制 `question_bank.db`，或使用 SQLite 的 backup API 创建一致快照。不要只复制仍运行的 WAL 数据库主文件。工具要求离线、已 checkpoint 的备份，并拒绝伴随非空 `-wal` 或 `-journal` 的源文件。

本仓库本地 `legacy/python` 保留旧代码与原始数据库。需要提取版本库中的旧快照时，在仓库根目录执行：

```bash
git show legacy/python:question_bank.db > /tmp/ocs-legacy-backup.db
```

该快照未必是部署环境的最新数据；不要推送整个旧分支或历史。历史密钥应在原服务商处撤销或轮换。

## 2. 只读预检

```bash
go run ./cmd/migrate -source /tmp/ocs-legacy-backup.db
```

默认只读，无需服务配置或 API key，也不创建目标数据库。输出包含总行数、无效行数、额外重复行数、冲突键数、可导入数量及原因统计，不输出题目和答案正文。

以下数据排除：题干为空、题型缺失/未知、选择题没有选项、答案为空、错误提示文本、未解析的 JSON/代码围栏。同一规范题目/选项/题型若存在不同答案，整组排除；相同答案重复只保留一条。

这些检查仅保证基本数据质量，不能证明答案事实正确或修复旧程序造成的缓存误用。请在源副本中人工审阅候选答案。

## 3. 审阅后导入

先备份已有 Go 数据库。目标由 `config.json` 的 `database` 指定，必须与源文件不同（包含硬链接检测）。配置使用实际部署的协议、端点和模型，以生成正确的缓存命名空间。

```bash
go run ./cmd/migrate -source /tmp/ocs-legacy-backup.db -config config.json -apply -reviewed
```

`-apply` 必须同时提供 `-reviewed`。读取服务配置需要相应密钥环境变量，但导入过程不发起任何模型请求。导入在单个事务内完成，任何插入错误都会回滚；已有缓存键不覆盖。重复执行不会增加重复记录。

导入来源标记为 `legacy-reviewed`，历史模型标记为 `unknown`，采用当前配置 TTL。不要把它误认为新模型重新生成的答案。

## 4. 切换与回退

1. Go 服务先使用独立端口和数据库副本。
2. 使用测试题确认三种协议中实际采用的协议、OCS handler、鉴权和超时设置。
3. 停止旧服务，把 OCS URL 切到新服务；保留旧程序和切换前备份。
4. 需要回退时停止 Go 服务，将 OCS URL 切回旧服务。不要让旧程序操作 Go 数据库，也不要覆盖当前数据库。

未在当前开发任务中迁移或修改实际生产数据库。
